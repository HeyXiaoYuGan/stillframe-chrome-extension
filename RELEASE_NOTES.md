# StillFrame 版本说明 / Release Notes

## v1.0.4

### 中文

- 新增“神秘入口”，用于尝试识别当前页面已加载且可直接保存的视频。
- “神秘入口”固定在品牌栏“定格”右侧，并随界面语言显示中文名或英文名。
- 优化当前页面多视频识别、列表恢复、封面回退和主播放器筛选。
- 修复部分视频网站 HLS 播放列表返回 412，以及相对分片丢失临时签名后返回 404 的问题。
- 下载前校验媒体响应并拒绝 HTML 错误页，避免生成只有几百字节的 `.htm` 假视频文件。
- 后台读取播放列表失败时，改由当前视频网页重新取得最终媒体播放列表，再交给后台下载分片。
- 视频预检被 CDN 拒绝时不再误判为无效地址；改由 Chrome 尝试下载，并自动清理实际返回的 HTML 错误页。
- 新增网页内读取方式：直接在当前播放器页面读取 MP4 或 HLS 分片并生成下载，后台方式仅作为回退。
- 使用 Mediabunny 的 HLS/MPEG-TS 解析与 MP4 无损封装作为首选合并引擎，原有顺序拼接保留为回退。
- HLS 子播放列表和分片先按标准相对 URL 请求；仅在失败时尝试继承上级临时参数，避免路径绑定签名触发 412。
- 所选 MP4 直链读取失败时，自动切换到相同或最接近清晰度的 m3u8 流继续下载。
- 修复 HLS 快速失败时结束消息先于任务登记到达、导致面板按钮持续锁定的问题。
- 清晰度列表仅保留已验证可读取的媒体：MP4 检查响应类型，m3u8 检查最终播放列表与首个分片。
- 清晰度检测采用六路并行短超时，HLS 分片采用四路并行读取，并在网页读取与合并期间持续显示进度。
- “神秘入口”改为手动识别：打开插件或切换面板时不再自动扫描，点击识别按钮后才读取当前页面。
- 手动识别任务由后台按标签页持续执行；关闭面板不会中断，重新打开可恢复识别状态与结果，页面跳转后才清除。
- 页面接口改为并行短超时读取，识别阶段显示播放器读取、媒体整理和清晰度验证的实时进度，并设置 60 秒任务上限。
- HLS 分片在网页与后台路径中均采用四路并行读取，Mediabunny 封装过程同步显示进度。
- 修复后台阶段进度先到、随后又被初始 8% 覆盖的问题；弹窗现在只接受向前推进的识别进度。
- 已验证的 MP4/WebM 下载不再重复扫描或整文件读入页面，直接交给 Chrome 下载管理器；HLS 默认进入后台任务，切换网页仍可恢复进度。
- 标题栏新增固定图标，可将插件打开为独立常驻窗口，避免普通扩展弹窗自动关闭。
- 固定功能改用 Chrome 原生侧边栏并绑定浏览器窗口，可随当前活动标签页读取网页，不再创建独立弹出窗口。
- 修复侧边栏从后台消息打开时丢失用户手势的问题；现在由固定按钮直接调用 Side Panel API。
- HLS 与 m3u8 回退不再执行依赖原网页的完整读取，直接进入 Offscreen 后台任务，切换标签页不会中断。
- 页面播放器解析增加 10 秒硬超时，超时后立即改用已捕获媒体；同时缩减全局对象和脚本扫描范围，避免进度长期停在 10%。
- 清晰度预检若整体被网站限制，不再删除播放器已经提供的全部候选；保留候选并标记为下载时再次验证。
- 页面对象扫描改为所有数据源共享总额度，播放器解析超时缩短至 6 秒，避免识别进度长期停在 20%。
- HLS 分片禁用失败缓存；遇到 404/412 会刷新播放列表并自动重试两次，同时移除可能与失败通知倒序显示的“已启动”系统通知。
- 播放器解析阶段每秒更新进度；Offscreen 分片读取失败后仅将失败分片交给原视频标签页读取，再返回后台继续合并。
- 识别中的面板每 750 毫秒向后台恢复一次真实状态；即使完成通知漏送，也会立即显示缓存结果，不再需要关闭后重开。
- 同一视频的下载文件名增加实际清晰度与格式标记，例如 `1080P-MP4`、`720P-HLS`，避免不同版本相互混淆。
- 轮询状态时优先读取后台已缓存的视频候选；即使最终完成状态尚未送达，当前面板也会立即展示结果并继续验证剩余清晰度。
- HLS 重试时通过原视频标签页重新获取最新 m3u8，替换过期播放列表后再下载分片。
- 专用 HLS 下载超过 500 MB 时改为写入浏览器 OPFS 临时文件，最高支持 4 GB，不再把全部分片保存在内存中。
- 不再根据分辨率套用默认码率估算大小；缺少真实长度或明确码率时显示“大小下载时确认”，避免与最终文件差异过大。
- 固定侧边栏移除任务列表，改为显示当前活动网页；上一页仍在运行的单个后台任务进度固定显示在面板最下方。
- 固定侧边栏允许继续识别新页面；已有下载或合并任务时，启动冲突任务会提示当前仅支持单任务。
- 完善图片与短视频扫描、筛选、画廊预览、批量下载和 ZIP 打包。
- 支持可见区域、完整页面以及 PNG、JPG、PDF 网页截图。
- 完善 Pinterest、抖音和 B站的专用保存流程与后台处理进度。
- 媒体解析、截图拼接、ZIP 生成及视频处理继续在浏览器本地完成。

### English

- Added “Secret Entry” for detecting directly savable videos already loaded by the current page.
- Fixed “Secret Entry” beside the StillFrame brand name and localized its label with the interface language.
- Improved multi-video detection, list restoration, cover fallback, and main-player filtering for the current page.
- Fixed HLS playlist 412 responses and 404 responses caused by relative segments losing temporary query signatures on some video sites.
- Validates media responses before downloading and rejects HTML error pages instead of saving tiny `.htm` files as videos.
- When background playlist access fails, obtains the final media playlist from the current video page before downloading its segments in the background.
- A CDN-rejected preflight no longer marks a video URL as invalid; Chrome attempts the download while actual HTML error responses are detected and removed.
- Added an in-page reader that downloads MP4 or HLS segments from the current player page and builds the download there, with the background path retained as a fallback.
- Uses Mediabunny HLS/MPEG-TS parsing and lossless MP4 remuxing as the preferred merge engine, retaining ordered concatenation as a fallback.
- Requests HLS child playlists and segments with standard relative URLs first, inheriting parent temporary parameters only as a fallback to avoid path-bound signature 412 responses.
- Automatically falls back from an unavailable MP4 URL to an m3u8 stream at the same or nearest quality.
- Fixed the panel remaining locked when a fast HLS failure arrived before the popup registered the background job.
- The quality list now keeps only verified readable media: MP4 response types are checked, while m3u8 entries require a readable media playlist and first segment.
- Quality checks now use six-way parallel short probes, HLS segments use four-way parallel reads, and in-page reading/remuxing continuously reports progress.
- “Secret Entry” now scans on demand: opening the extension or switching panels performs no scan until the detect button is clicked.
- Manual detection now continues per tab in the background when the panel closes; reopening restores its state and results, while navigating away clears them.
- Page endpoints now use parallel short-timeout reads; detection reports player, media, and quality-validation progress and has a 60-second task deadline.
- HLS segments now use four-way parallel reads in both page and background paths, with Mediabunny remux progress displayed in the panel.
- Fixed early background progress being overwritten by the initial 8%; the popup now accepts only forward-moving detection progress.
- Verified MP4/WebM downloads now skip duplicate scanning and in-page full-file buffering, going directly to Chrome; HLS starts as a background job whose progress can be restored after switching pages.
- Added a header pin control that opens the extension as a persistent standalone window.
- The pin control now uses Chrome's native side panel for the browser window, following the active web tab instead of creating a standalone popup window.
- Fixed side-panel opening losing the user gesture through background messaging; the pin button now calls the Side Panel API directly.
- HLS and m3u8 fallback no longer perform a full read tied to the source page and start directly as Offscreen background jobs, so switching tabs does not interrupt them.
- Page-player extraction now has a hard 10-second deadline and immediately falls back to captured media; global-object and script scanning were also reduced to prevent progress remaining at 10%.
- If all quality probes are blocked by the site, player-provided candidates are retained and marked for validation again at download time instead of being removed entirely.
- Page-object inspection now shares one global budget across all sources and player extraction times out after 6 seconds, preventing detection progress from remaining at 20%.
- HLS segments bypass failed cache entries; 404/412 responses refresh the playlist and retry twice, while the potentially out-of-order “started” system notification has been removed.
- Player extraction now updates progress every second; when an Offscreen segment fetch fails, only that segment is fetched through the original video tab and returned to the background merge.
- While detection is active, the panel restores the authoritative background state every 750 ms, so cached results appear even if a completion message is missed without requiring the panel to be reopened.
- Download filenames for the same video now include the actual quality and format, such as `1080P-MP4` or `720P-HLS`, to distinguish variants.
- Status polling now reads cached video candidates first, allowing the open panel to display results immediately while remaining qualities continue validating even if the final completion state has not arrived.
- HLS retries now refresh the latest m3u8 through the original video tab and replace the expired playlist before downloading segments again.
- Dedicated HLS downloads larger than 500 MB now stream into a temporary browser OPFS file, supporting up to 4 GB without retaining every segment in memory.
- Removed resolution-only default bitrate estimates; when no real length or explicit bitrate is available, the UI shows “Size confirmed on download” instead of a misleading number.
- Removed the task list from the pinned side panel; it now follows the active webpage while the single previous background task remains fixed at the bottom.
- The pinned side panel can continue detecting a new page; starting a conflicting download or merge displays the current single-task limitation.
- Improved image and short-video scanning, filtering, gallery preview, batch downloads, and ZIP packaging.
- Added visible-area and full-page capture with PNG, JPG, and PDF output.
- Improved dedicated saving workflows and background progress for Pinterest, Douyin, and Bilibili.
- Media parsing, screenshot stitching, ZIP generation, and video processing continue to run locally in the browser.
